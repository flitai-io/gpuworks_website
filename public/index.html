从接入到服务

一条完整、可解释的 GPU 工作流

不是一组松散脚本。资源探测、模型与镜像、调度、运行时和观测围绕同一份期望状态协同工作。

01

异构节点统一接入

agent 主动通过 WebSocket 外连控制面，适合内网、NAT 和租用容器。探测 NVIDIA、昇腾与 PPU 的设备、拓扑和运行指标。

Node→WSS / yamux→Server
02

显存估算与拓扑调度

提交前拆解权重、KV cache、CUDA graph 与预留显存，自动选卡并解释调度结果。

03

vLLM / SGLang 部署

引擎参数由服务端下发，支持多机推理、实例状态机、启动日志和 OpenAI 兼容入口。

04

模型与离线镜像

支持 Hugging Face、ModelScope、断点续传、节点间同步，以及带摘要校验的离线镜像包。

05

切分、休眠与唤醒

x86 NVIDIA 节点可用 HAMi 限制显存；空闲实例可 sleep，使用时再 wake，释放昂贵显存。

06

监控、日志与评测

内嵌时序指标和全文日志检索；纯 Go 评测引擎输出吞吐、TTFT、TPOT、P50/P99 与 Pareto 结果。

三步开始

安装指南

控制面与 agent 都是 CGO_ENABLED=0 的静态二进制。控制面不要求 Python、venv 或系统 glibc。

  1. 1

    下载并启动控制面

    在一台 Linux 主机上选择对应架构，校验、解压并启动：

    curl -fLO https://gpuworks.zstack.ai/downloads/<安装包>
curl -fLO https://gpuworks.zstack.ai/downloads/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf gpuworks-*.tar.gz
cd gpuworks-*
./gpuworks serve --addr :8800 --data ./data \
  --public-url https://gpu.example.com

    首次启动会打印 admin 密码和默认 API key，各只显示一次。请立即保存并通过反向代理启用 HTTPS。

  2. 2

    在控制台创建节点

    打开控制面，进入「计算节点 → 添加节点」。系统会创建节点专属 token，并给出完整安装命令。token 不写在公共安装脚本里。

  3. 3

    在 GPU 节点执行接入命令

    curl -fsSL https://gpu.example.com/install.sh | sh -s -- \
  --server https://gpu.example.com --token <节点专属 token>

    有 Docker 时自动使用 Docker driver；无 root/daemon 的共享容器可回退到 udocker。agent 默认主动外连，不监听入站端口。

安装前确认

控制面Linux amd64 / arm64；可被节点访问的 HTTP(S) 地址；持久化数据目录。
NVIDIA 节点nvidia-smi 可用；容器推理建议安装 Docker + NVIDIA Container Toolkit。
昇腾节点npu-smi、Docker 与 Ascend runtime 可用；使用匹配 CANN 的推理镜像。
多机推理每台节点配置其他 rank 可达的 direct address，并允许临时 preflight/master 端口通信。

常见问题

这是稳定版吗？可以直接上生产吗？

目前是按 master commit 构建的预览版，并非语义化稳定发行。CI 能证明仓库定义的自动检查结果，但不能替代你的驱动、GPU 型号、推理镜像、模型和网络条件验收。

为什么只下载 server，没有单独的 agent 包？

server 二进制内嵌 Linux amd64 和 arm64 agent，并通过自己的 /dl/ 路径分发。节点页生成的安装命令会自动识别架构、下载并启动 agent。

agent 是否需要开放端口？

默认 agent_dial 模式不需要：agent 主动外连 server。多机推理需要节点间双向可达；可选 server_dial 模式也需要 server 能访问 agent 的监听端口。

支持哪些 GPU 和推理路径？

NVIDIA 支持探测、容器推理和 x86 HAMi 显存切分；昇腾支持探测及 Docker + Ascend runtime 推理；PPU 已支持设备探测和库存呈现，但容器推理仍取决于可用的厂商 runtime，当前公开真机环境未验证该路径。

如何升级？数据会丢吗？

server 通过替换二进制并重启升级，数据库会自动迁移；升级前仍应备份数据目录。agent 可在节点页触发升级，也可重跑 /install.sh，下载完成后原子替换。

代码是开源的吗？采用什么许可证？

当前发布站提供可执行预览包，项目仓库为组织内部可见，仓库根目录尚未声明开源许可证。因此请勿自行推定开源授权；对外分发与商用条款以 ZStack 后续正式发布说明为准。

真机 case 增删或改名后，页面需要手工维护吗？

不需要。页面按 GitLab job 的 stage 动态发现 cloud-smoke 与 cloud-full case。新增 job 会自动出现；删除的 job 在最近 20 条 pipeline 窗口内仍保留历史，随后自然退出；改名会暂时显示为两个独立 case，避免把不同测试口径错误合并。

CI 通过率是怎么计算的？

页面从 GitLab API 定时读取最近 master pipeline 和 job。每个真机用例的通过率为 success ÷ (success + failed)；skipped、manual、canceled、running、pending 和 waiting_for_resource 不进入分母。页面同时展示有效样本数、明确记录的跳过/未执行数、最近有效结果、最近成功时间与该次成功耗时，避免脱离样本量解读百分比。
